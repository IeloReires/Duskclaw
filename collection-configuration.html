Activer la collection personnelle

La page collection.html est prête, mais elle a besoin d’un service sécurisé pour les comptes. Le site Duskclaw étant hébergé comme des pages statiques, les mots de passe et les collections ne doivent pas être enregistrés directement dans les fichiers du site.

  1. Crée un projet Supabase et conserve les identifiants du projet de façon privée.
  2. Dans Supabase, ouvre SQL Editor, puis copie-colle le contenu de collection-securite.sql et exécute-le. Cela crée la table et les protections qui limitent chaque compte à ses propres cartes.
  3. Dans la configuration d’authentification, garde la confirmation de l’adresse e-mail activée. Configure une longueur minimale de mot de passe de 12 caractères et des caractères variés. La page demande déjà 12 caractères, mais la règle doit aussi être appliquée côté service.
  4. Dans les réglages d’URL d’authentification, ajoute l’adresse exacte du site Duskclaw et l’adresse de la page collection.html comme redirections autorisées. Pour le site actuel, ce sera sous https://ieloreires.github.io/Duskclaw/.
  5. Dans les paramètres API du projet, récupère l’URL du projet et la clé publishable (ou l’ancienne clé publique anon). Dans collection.html, remplace YOUR_SUPABASE_PROJECT_URL et YOUR_SUPABASE_PUBLISHABLE_KEY par ces deux valeurs.
  6. Téléverse collection.html à la racine du dépôt GitHub. La page sera accessible à https://ieloreires.github.io/Duskclaw/collection.html.
À ne jamais mettre dans le HTML ni partager : la clé secrète Supabase, l’ancienne clé service_role, le mot de passe du projet ou le mot de passe d’un utilisateur. Seule la clé publique “publishable/anon” est prévue pour le navigateur, et uniquement avec les règles SQL de sécurité installées.

Teste d’abord avec deux comptes à toi : ajoute une carte sur le premier, connecte-toi avec le second et vérifie qu’il ne la voit pas. Avant d’ouvrir les inscriptions à tout le monde, ajoute aussi une page de confidentialité et une procédure de suppression de compte. Les comptes par e-mail impliquent de gérer ces demandes de manière fiable.

Supabase s’occupe de l’authentification et du hachage des mots de passe ; les politiques RLS limitent l’accès aux données de chaque compte. Voir la documentation officielle Auth, les réglages de sécurité des mots de passe et la documentation RLS.
